# MES JIT Kitting & Operations Bottleneck Architecture
[วันที่บันทึก: 2026-08-27]

---

## 1. บริบทและปัญหาหน้างานเดิม (Operational Pain Point)
ในการดำเนินงาน Rework (RT/RW) ของโรงงาน OEM เดิมมีปัญหาคอขวดเรื้อรังที่จุดเชื่อมต่อระหว่างฝ่ายคลังภาชนะ (WPK) และฝ่ายผลิตซ่อม (PDF):
1. **การเบิกล่วงหน้าก่อนการวิเคราะห์ (Premature Requisition)**: WPK ดึงกล่องมารอล่วงหน้าตั้งแต่ได้รับอีเมลแจ้งเปิดเคส แต่ยังไม่ทราบสเปกและชิ้นส่วนไส้ในที่ต้องใช้จริง (แกลลอน, ฝา, ฟอยล์, น้ำมัน)
2. **การเบิกสองรอบ (Double Handling Waste)**: WPK ต้องหยิบและขนส่ง 2 รอบ และกล่องเปล่าถูกนำมากองเกะกะหน้าไลน์เสี่ยงต่อความเสียหาย
3. **ช่องโหว่การโยนความรับผิดชอบ (Missing Two-Way Handshake)**: WPK อ้างว่าจ่ายกล่องแล้ว แต่ของจริงขาดแกลลอน ส่งผลให้งานค้าง และ PDF ถูกมองว่าซ่อมช้า

## 2. สถาปัตยกรรมทางแก้: Closed-Loop JIT Single-Batch Kitting

```
[1. เปิดเคส RT/RW]
       │
       ▼ (ไม่อนุญาตให้เบิกของก่อน บันทึกแค่ข้อมูลเคส)
[2. QSMS วิเคราะห์หน้างาน & ระบุสเปก]
       │ ➔ ระบบสรุป Bill of Materials (BOM) ทั้งหมดทันที:
       │    (เช่น กล่อง 10 ใบ + แกลลอน 20 ใบ + ฝา 20 ชิ้น + น้ำมัน 2L)
       ▼
[3. WPK ได้รับ Order เดียว ➔ จัดของครบชุด (Kit) ในรอบเดียว ➔ ส่งมอบให้ PDF]
       │
       ▼
[4. Two-Way Handshake: PDF ตรวจนับและกดยืนยันรับในระบบ]
       ├─ [กรณีรับครบ 100%] ➔ สถานะเป็น "กำลังผลิตซ่อม (In-Progress)" (PDF ซ่อมรวดเดียวจนจบ)
       └─ [กรณีของขาดบางรายการ] ➔ สถานะเป็น "Blocked: รอ WPK จ่ายของเพิ่ม" (ความรับผิดชอบอยู่ที่ WPK ในแดชบอร์ด)
```

## 3. ระบบแดชบอร์ดชี้เป้าคอขวด 5 ขั้นตอน (Operations Flow & Bottleneck Monitor)
ระบบแดชบอร์ดใน `Dashboard.tsx` ถูกพัฒนาเพื่อติดตาม Lifecycle ครบ 5 ขั้นตอน:

1. **`Pending Analysis`** ➔ ฝ่าย **QSMS (QC)** ถือเคส: กำลังตรวจสอบและระบุสเปกภาชนะ/สูตร
2. **`Awaiting Materials`** ➔ ฝ่าย **WPK (Store)** ถือเคส: รอการจัดชุดและเบิกจ่ายบรรจุภัณฑ์
3. **`In-Progress`** ➔ ฝ่าย **PDF (Production)** ถือเคส: ของครบแล้ว กำลังผลิตซ่อมในสายงาน
4. **`Blocked`** ➔ **Defend / จุดติดปัญหา**: วัสดุขาด (ขาดกล่อง/แกลลอน/น้ำมัน) หรือรอผลแล็บ
5. **`Completed`** ➔ **เสร็จสมบูรณ์ 100%**: ปิดเคส

### กลไก Operations Bottleneck Radar
- ระบบคำนวณเคสและยอดกล่องคงค้างของแต่ละฝ่ายแบบ Real-time
- คำนวณหาฝ่ายที่มีคิวงานคั่งค้างสูงสุดเพื่อแสดงแถบแจ้งเตือน **"🔥 จุดคอขวดสูงสุด"**
- รองรับ 1-Click Interactive Cross-Filter บนการ์ดแผนก เพื่อกรองตารางงานเฉพาะฝ่ายได้ทันที

## 4. สถาปัตยกรรมการแจ้งเตือน 3 ระดับ (3-Tier Alert Architecture)
1. **LINE Push Notification**: ยิง Flex Message เข้ากลุ่ม LINE ของ WPK เมื่อ QSMS สั่งเบิก และยิงเข้ากลุ่ม PDF เมื่อ WPK จ่ายของเสร็จ
2. **In-App Notification Bell & Sound**: ไอคอนกระดิ่งพร้อม Badge สีแดงและเสียงเตือนเมื่อมีงานใหม่เข้าคิวของตนเอง
3. **Role-Based Task Queues**: หน้าต่างแรกหลังล็อกอินจะเปิดคิวงานเฉพาะของบทบาทตนเอง (WPK Queue / PDF Ready-to-Repair Queue) ทันที
